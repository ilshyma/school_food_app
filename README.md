# 🍲 Замовлення шкільного харчування

Архитектура: **БД** — Google-таблица, **движок** — `Code.gs` (Apps Script), **UI** — `Index.html`
(веб-страница, которую Google бесплатно хостит через Deploy → Web app). Сервер не нужен.

## Установка (один раз, ~10 минут)

1. Откройте вашу таблицу-прототип → **Extensions → Apps Script**.
2. В файл `Code.gs` вставьте содержимое [Code.gs](Code.gs) (старый код скрипта можно
   оставить в отдельном файле или удалить — меню создаёт этот код).
3. **File → New → HTML**, назовите файл `Index`, вставьте содержимое [Index.html](Index.html).
   Ещё один **File → New → HTML** с именем `Admin` — содержимое [Admin.html](Admin.html) (админ-панель).
4. Сохраните, вернитесь в таблицу, обновите страницу — появится меню **«🍲 Харчування»**.
5. Меню → **«1. Створити/оновити службові листи»** (при первом запуске Google попросит
   разрешения — подтвердите). Появятся листы: Налаштування, Список, Ціни, Правила змін,
   Меню, МенюДані, Замовлення, Оплати, Токени, Зведення, Баланс, Журнал змін.
6. Заполните лист **«Список»** (заголовки строго в 1-й строке):

   | ПІБ | Клас | Телефон 1 | Телефон 2 | Статус | Email 1 | Email 2 | Примітка |
   |---|---|---|---|---|---|---|---|
   | Старушенко Майя | 3 | +380671234567 | 0509876543 | активний | mama@gmail.com | | усе меню автоматично |

   - «Клас» — выпадающий список 0–6. Если лист был в старом порядке колонок,
     пункт 1 меню переставит их сам, сохранив данные (сопоставление по заголовкам).

   - Вход в форму — по телефону **или** email; email также нужен для уведомлений.

   - Формат телефона не важен — скрипт сравнивает последние 9 цифр.
   - Пустой статус = активний. «архів» — ребёнок скрыт из формы, но история и баланс сохраняются.
7. Проверьте цены в листе **«Ціни»**. Цены версионируются: колонка «Діє з (дата)» —
   с какого дня действует строка (пусто = с начала). При изменении цены добавьте новую
   строку с датой; для недели берётся цена, действующая на её понедельник, уже сохранённые
   недели не пересчитываются.
8. **Deploy → New deployment → Web app**:
   - Execute as: **Me**
   - Who has access: **Anyone**
   - Скопируйте URL веб-приложения и вставьте его в «Налаштування» → «URL веб-додатку».

## Еженедельный цикл (админ, ~2 минуты)

1. В школьной таблице откройте лист «Склад …», выделите всё (Ctrl+A), скопируйте
   и вставьте в лист **«Меню»** (поверх старого).
2. Меню → **«2. Розібрати меню з листа «Меню»»** — скрипт разложит блюда по дням/приёмам.
3. В **«Налаштування»** поставьте дату понедельника новой недели — дедлайн первичного
   заказа (по умолчанию «воскресенье 17:00») пересчитается автоматически (строка
   «Дедлайн першого замовлення (авто)», там формула — не редактировать).
   После дедлайна форма переходит в режим из «Після дедлайну»: по умолчанию —
   точечные изменения по листу **«Правила змін»** (сніданок — до 17:00 предыдущего дня,
   обід/підвечірок — до 09:30 того же дня; всё настраивается дропдаунами).
   «Тиждень закрито» = так — аварийное закрытие всего.
4. Разошлите родителям ссылку (или персональные ссылки из листа «Токени» —
   меню → пункт 3; тогда родителям даже телефон вводить не надо).

## Как это работает для родителя

Открыл ссылку → ввёл телефон (один раз, дальше запоминается) → видит **только своих детей** →
по каждому дню выбирает Сніданок/Обід/Підвечірок №1/№2 с описанием блюд и ценой →
внизу живая сумма за неделю → «Зберегти». Повторный вход до дедлайна = изменение/отмена
(тот же экран, старый выбор подставлен).

## Учёт

- **«Замовлення»** — БД: один рядок = ребёнок+неделя, 15 выборов, сумма, кто и когда сохранил.
- **«Зведення»** — лист для передачи кейтерингу: только количество порций, ничего лишнего.
  Тот же вид, что и «Підрахунки» в оригинальной школьной таблице: 5 блоков
  «День | Підрахунки» рядом, в каждом — Сніданок/Обід/Підвечірок по вариантам №1/№2.
  Числа не записываются скриптом, а считаются формулами `COUNTIFS` по листу «Замовлення»,
  поэтому обновляются сами, как только родитель меняет заказ.
  Кто не ответил — видно в админ-панели («Порції на день», строки с «—»).
- **«Оплати»** — админ вписывает платежи (дата, ПІБ, сумма).
- **«Баланс»** — по каждому ребёнку: заказано за всё время / оплачено / баланс.
- **«Журнал змін»** — каждое сохранение родителя: кто, когда, «Вт Обід: №1 → —»,
  с пометкой «после дедлайна». Передали кейтерингу — пункт меню
  «Позначити зміни як передані кейтерингу».

## Админ-панель и email

- Меню → **«Показати посилання на адмін-панель»** → ссылка `…/exec?admin=<токен>`:
  вкладки «Порції на день» — сверху таблица «ПІБ × Сніданок/Обід/Підвечірок» (прямая
  связка имени и выбранного варианта на конкретный день), ниже — карточки по вариантам
  с составом блюд и списком имён, кнопка печати; «Внести оплату»; «Діти» — список
  карточками (телефоны, email, статус, примітка, баланс, добавление), одинаково
  удобно на компьютере и на телефоне.
- Меню → **«Увімкнути нагадування та email-сповіщення»** (один раз): ежечасный триггер
  напоминает семьям без заказа за N часов до дедлайна («Нагадування: за годин до дедлайну»
  в Налаштуваннях), триггер на «Оплати» шлёт письмо о зачислении.
- Меню → **«Надіслати баланси на email»** — рассылка текущего баланса всем семьям с email.
- В шапке формы родитель видит баланс на начало недели; при 2+ детях — экран выбора ребёнка.

## Безопасность

- Поиск детей по телефону идёт на сервере — список детей и телефонов в браузер не попадает.
- Персональная ссылка `?key=…` — случайный токен; отозвать = удалить строку в «Токени».
- Админ-панель `?admin=…` — токен из «Налаштувань»; утёк → очистить ячейку и запустить пункт 1.
- Сохранение проверяет на сервере: дедлайн не прошёл и ребёнок действительно привязан
  к этому номеру.
