# Деплой і оновлення

## Головне правило

> **Збереження коду в редакторі не змінює того, що бачать батьки.**

Код у редакторі — чернетка. Батьки працюють з **версією**, зафіксованою в розгортанні (деплої).
Поки ви не випустили нову версію, за посиланням `/exec` працює старий код.

Зміни в **таблиці** (налаштування, ціни, діти, меню) деплою не потребують — діють одразу.

## Перший деплой

Редактор Apps Script → **Deploy → New deployment** → ⚙ біля «Select type» → **Web app**:

| Поле | Значення | Чому |
|---|---|---|
| Description | `v1` | довільний підпис, видно у списку версій |
| **Execute as** | **Me** (ваша пошта) | скрипт працює від імені власника й має доступ до таблиці. «User accessing the web app» — батьки отримають помилку доступу |
| **Who has access** | **Anyone** | форма відкривається без входу в Google. «Anyone with Google account» змусить кожного логінитися, «Only myself» закриє форму для всіх, крім вас |

**Deploy** → скопіюйте **Web app URL** (`https://script.google.com/macros/s/…/exec`) →
«Налаштування» → **URL веб-додатку**.

Під час першого деплою Google може ще раз попросити дозволи — **Advanced → Go to … (unsafe) → Allow**.

## Оновлення коду — найчастіша операція

1. Вставте новий код у `Code.gs` / `Index.html` / `Admin.html` → **Save**.
2. Таблиця → меню → **1. Створити/оновити службові листи** (якщо в новій версії з'явилися листи, колонки чи налаштування — пункт їх додасть без втрати даних).
3. **Deploy → Manage deployments** → ✏️ на наявному розгортанні → **Version: New version** →
   (Description: що змінилося) → **Deploy**.

URL залишається тим самим.

> ❌ **Не робіть «New deployment» для оновлення.** Це створює **нову адресу**, а стара далі працює
> зі старим кодом. Класична пастка «я все виправив, а нічого не змінилося»: батьки ходять
> за старим посиланням.
>
> **New deployment — один раз у житті. Далі — тільки New version.**

## Перевірити, що оновлення доїхало

1. Відкрийте форму в **анонімному вікні** (`Ctrl+Shift+N`, на Mac `Cmd+Shift+N`) — звичайне вікно може показати кеш.
2. **Deploy → Manage deployments** — номер версії активного розгортання має бути новим.
3. Якщо щось не працює — ліва панель редактора → **Executions**: кожен виклик, статус, текст помилки.

## Тестова адреса /dev

**Deploy → Test deployments** дає адресу, що закінчується на `/dev`. Вона **завжди показує
поточний код з редактора**, без випуску версії, але відкривається тільки вам (під акаунтом власника).

Робочий процес для змін: правите код → перевіряєте на `/dev` → усе добре → **New version** для `/exec`.
Адресу `/dev` батькам не давати — у них вона не відкриється.

Адмінпанель на тестовій адресі: `…/dev?admin=<ключ>`.

## Відкат до попередньої версії

Нова версія зламала форму:

**Deploy → Manage deployments → ✏️ → Version: оберіть попередній номер → Deploy**

За 10–20 секунд `/exec` знову працює на старій версії. Код у редакторі при цьому не змінюється —
виправляйте його окремо або візьміть робочий файл з репозиторію.

## Кілька розгортань у списку

Має бути **одне** активне розгортання вебдодатку. Якщо помилково створено кілька:
1. з'ясуйте, яку адресу роздано батькам (вона в «Налаштуваннях» і в листі «Токени»);
2. решту — **Archive** (три крапки біля розгортання). Архівне розгортання перестає відкриватися.

## Якщо адреса все-таки змінилася

1. Нову адресу — у «Налаштування» → **URL веб-додатку**.
2. Меню → **3. Згенерувати персональні посилання** — посилання в «Токенах» оновляться (ключі ті самі).
3. Меню → **Показати посилання на адмін-панель** → оновіть закладки.
4. Повідомте батькам нове загальне посилання. Старі персональні посилання не працюватимуть —
   розішліть нові або попросіть увійти за номером.
