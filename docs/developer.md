# Для розробника

## Архітектура

Контейнерний проєкт Google Apps Script (V8), прив'язаний до Google-таблиці. Таблиця — база даних,
`doGet` віддає HTML через `HtmlService`, клієнт викликає сервер через `google.script.run`.

| Файл | Роль |
|---|---|
| `Code.gs` | увесь сервер: схема листів, час, налаштування, правила, API батьків і адміна, пошта, тригери, звіти, імпорт, демо |
| `Index.html` | SPA для батьків: вхід → вибір дитини → тиждень. Шаблон, `<?= key ?>` підставляє ключ з URL |
| `Admin.html` | SPA адміністратора: порції, оплати, діти. `<?= admin ?>` — адмін-ключ |

Маршрутизація `doGet(e)`: `?admin=<ключ>` і ключ збігається з «Адмін-токеном» → `Admin`, інакше → `Index`
(`?key=` передається в шаблон). Обидва параметри очищаються до `[A-Za-z0-9]`.

## Модель даних

- **Ключ дитини — рядок ПІБ.** Жодних прихованих id. Зв'язки: «Список».A ↔ «Замовлення».B ↔ «Оплати».B ↔ «Журнал змін».C.
  Перейменування — лише через `renameEverywhere()` (його викликає `api_admin_saveChild`).
- **Ключ замовлення — (ярлик тижня, ПІБ).** Ярлик `dd.MM-dd.MM` рахується з понеділка (`weekLabelOf`).
- **15 виборів** у фіксованому порядку: індекс `i = день × 3 + прийом`, `DAYS`×`MEALS`. `CHOICES = ['№1','№2','—']`.
- **Сума тижня** обчислюється при збереженні й заморожується в колонці R.
- **Баланс** не зберігається — `computeBalances()` щоразу сумує «Замовлення».R і «Оплати».C. Лист «Баланс» — лише знімок.
- **«Зведення»** — `COUNTIFS`-формули; перебудовується, коли `summaryStale()` бачить інший тиждень.

## Час

`TZ = 'Europe/Kyiv'` жорстко. Календарна арифметика — на `{y, mo, d}` без годин (`ymdOf`, `ymdAdd`, `ymdWeekday`),
перетворення в момент часу — лише через `atTime(ymd, {h, m})` = `Utilities.parseDate(..., TZ)`.
Так DST і часовий пояс акаунта не впливають. `setupSheets()` ставить таблиці той самий пояс,
щоб формула дедлайну в «Налаштуваннях» збігалася з серверним розрахунком.

## Дозволи на прийоми

`cellPermissions(st, rules)` → масив з 15 `{c, x, ct, xt}`: чи можна змінити/дозамовити (`c`), скасувати (`x`),
і тексти дедлайнів. Порядок перевірок: `closed` → до дедлайну або `вільно` (усе можна) → `заборонено` → вікна з «Правил змін».
Клієнт (`optAllowed`) і сервер (`api_save`) застосовують однакову логіку; **сервер — джерело правди**.

## Серверний API (`google.script.run`)

| Функція | Хто | Що робить |
|---|---|---|
| `api_init(p)` | батьки | `p` — один з `{key}`, `{contact}`, `{auto}` → діти, тиждень, дозволи, ціни, меню, баланс на початок тижня, збережені вибори. Створює токен контакту |
| `api_save(p)` | батьки | `p = {key, child, choices[15]}` → перевіряє прив'язку, дедлайни, вікна; пише замовлення й журнал під `LockService` |
| `api_admin_today(token, 'yyyy-MM-dd', classes[])` | адмін | порції на день: таблиця ПІБ × прийоми, варіанти з іменами, фільтр класів |
| `api_admin_roster(token)` | адмін | усі діти з балансами |
| `api_admin_saveChild(token, c)` | адмін | `c.row` є → оновлення (перевірка `c.orig`, перейменування з перенесенням історії), немає → додавання |
| `api_admin_addPayment(token, p)` | адмін | рядок в «Оплати», перерахунок, лист |
| `api_statement(p)` | батьки | `p = {key, child, from, to}` (`yyyy-MM-dd`) → виписка; перевіряє прив'язку дитини |
| `api_admin_statement(token, p)` | адмін | `p = {name, from, to}` → виписка по будь-якій дитині зі «Списку» |

Усі повертають `{error: '…'}` замість винятків — клієнт показує текст як є.

## Безпека

- Батьки ніколи не отримують список дітей чи контактів: пошук `childrenByContact()` — на сервері.
- `api_save` повторно перевіряє, що `child` прив'язаний до контакту з токена.
- Токени — `Utilities.getUuid()`, 10 символів для родин, 16 для адміна. Відкликання — видалення рядка / очищення клітинки.
- `resolveContact({auto})` пробує `Session.getActiveUser()` — працює лише в межах одного домену Workspace.
- Вебдодаток виконується від імені власника («Execute as: Me»), тому доступ до таблиці батькам не потрібен.
- Увесь вивід у HTML проходить через `esc()`.

## Виписка

`buildStatement(name, from, to)`:

- нарахування — з «Замовлень» по днях (`ymdAdd(monday, d)`), ціни — `getPrices(monday)`;
- різниця між замороженою «Сумою» (R) і розрахунком → поле `fix` в останній день харчування тижня,
  тож `closing` за весь час = `computeBalances()`;
- рік тижня — `mondayFromLabel(label, near)`: ярлик `dd.MM-…` + дата поруч (колонка «Оновлено» / «Час» журналу);
  з років `near±1` обирає той, де дата — понеділок і найближча;
- оплати без дати → у `opening`;
- зміни з «Журналу змін» парсяться з тексту `Вт Обід: №1 → —` і прив'язуються до дня.

Відповідь: `{opening, paid, charged, closing, rows:[{kind:'day'|'pay', date, label, amount, balance, items, changes, fix, future, comment}]}`.
Рендер — у `statementHtml()` обох HTML (копія, бо файли незалежні).

## Меню й новий тиждень

- `parseMenuValues(vals)` — розбір «Склад …» у рядки «МенюДані» + `missing` (яких з 30 позицій немає).
- `loadMenu(st, label, forceManual)` — джерело: лист `st.cateringMenuTab` (`{тиждень}` → label) з таблиці кейтерингу
  з перевіркою тижня за назвою листа/файлу, інакше лист «Меню». `canFallback` — можна запропонувати ручний режим.
- `applyMenu(m)` — копія їхнього листа в «Меню» + `writeMenuData`.
- `openNewWeek()` — `ui.prompt` з пропозицією понеділка (`активний + 7` або найближчий), `parseDmy`,
  перевірка понеділка, меню, підсумок, запис дати в «Налаштування», `refreshSummary`, `sendNewWeekEmails`.
- `sendNewWeekEmails(st)` — один лист на адресу (`familiesWithEmail`), прапорець `announced_<тиждень>`.
- «Налаштування» будує `setupSettings()` за `SETTINGS_LAYOUT` (блоки, пояснення); рядки-заголовки мають префікс `■`,
  `getSettings()` їх просто ігнорує.

## Передача кейтерингу

Ідея: у кейтеринг іде лише кількість порцій; діти лишаються в нас.

- `cateringPlan(st)` — відкриває таблицю (`openTarget`), шукає лист за `fillWeek(st.cateringTab)` або за `gid`
  з посилання, перевіряє тиждень за назвами листа/файлу, знаходить заголовки днів і 30 рядків
  `/^(Сніданок|Обід|Підвечірок)\s*№?\s*([12])$/`; кількість — клітинка праворуч. Повертає `slots` з поточними
  значеннями й ознакою формули, `errors`, `warnings`.
- `cateringDiff` — порівняння з `countsForWeek()` (ті самі числа, що формули нашого «Зведення»).
- `cateringWrite` — `setValue` лише змінених клітинок, `flush`, перечитування всіх 30 і звірка.
- `cateringMenu` — ручний запуск з діалогами. `cateringTick` — тригер кожні 15 хв: підпис
  `тиждень|JSON(кількості)` у Script Properties (`cat_last`), без змін — вихід; попередження → не пише;
  помилки → `cateringAlert` (журнал + один лист власнику на унікальну проблему, `cat_alert`).
- Журнал — лист «Кейтеринг: журнал» (`logCatering`).

`SpreadsheetApp.openByUrl` потребує повного дозволу `spreadsheets` — перший запуск може попросити переавторизацію.

## Тригери

- `reminderTick` — щогодини; вікно `[дедлайн − N год, дедлайн]`; раз на тиждень, прапорець `reminded_<тиждень>` у Script Properties.
- `onPaymentEdit` — інстальований `onEdit` на таблицю; шле лист, коли рядок «Оплат» повний і «Повідомлено» порожнє.
- `cateringTick` — кожні 15 хв; діє лише з «Кейтеринг: автопередача» = так.

## Як змінити типові речі

**Діапазон класів.** `Code.gs`: випадні списки `['0'…'6']` у `setupSheets` («Список» і «Імпорт»),
регулярний вираз `/^[0-6]$/` в `importFromSheet`. `Admin.html`: `var CLASSES = [...]`. Потім пункт 1 меню.

**Ціни за замовчуванням.** `setupSheets` → блок «Ціни» (лише для порожнього листа).

**Стандартні правила змін.** `DEFAULT_RULES` + початкові рядки в `setupSheets` → «Правила змін».

**Третій варіант або четвертий прийом.** Зачіпає `MEALS`/`CHOICES`, `orderHeaders()` (колонки «Замовлень»),
жорсткі індекси (`r.slice(2, 17)`, `r[17]` — сума, `15` виборів у `api_save`), `refreshSummary`, обидва HTML.
Це міграція схеми — робіть на копії таблиці.

**Нове налаштування.** Додайте назву в `ORDER`, значення за замовчуванням у `DEFAULTS`, формат у `CELL_FORMATS`
(`setupSheets`), читання в `getSettings()`.

## Локальна перевірка

Node не обов'язковий: на macOS є JavaScriptCore.

```bash
JSC=/System/Library/Frameworks/JavaScriptCore.framework/Versions/A/Helpers/jsc
```

Синтаксис:

```js
// check.js
var src = readFile('Code.gs');
try { new Function(src); print('OK'); } catch (e) { print(e.message); }
```

Логіку можна ганяти, підклавши фейкові `sheet()`, `SpreadsheetApp.getUi()` і об'єкти листів з
`getRange().getValues()/setValues()` поверх масивів, і дописавши їх **після** `Code.gs` в один файл —
пізніші оголошення функцій перекривають ранні.

## Реліз

1. Зміни в репозиторії → коміт.
2. Вставити файли в редактор Apps Script (або `clasp push`).
3. Меню → пункт 1, якщо змінювалась схема.
4. **Deploy → Manage deployments → ✏️ → New version**.
5. Перевірка в анонімному вікні, **Executions** без помилок.

Документація — у `docs/`, збирається GitHub Pages (Jekyll, тема just-the-docs). Правка будь-якої
сторінки — кнопка «Виправити цю сторінку на GitHub» внизу.
