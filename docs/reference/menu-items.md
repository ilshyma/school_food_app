# Меню «🍲 Харчування»

Меню з'являється у верхньому рядку таблиці через кілька секунд після відкриття. Запускайте пункти
**з таблиці**, а не кнопкою Run у редакторі коду: більшість пунктів показують підсумкове вікно,
і поки його не закрито, скрипт чекає (див. [Проблеми](../troubleshooting.md)).

| Пункт | Що робить | Коли | Повторно |
|---|---|---|---|
| **▶ Новий тиждень: меню, дати, лист батькам** | пропонує наступний понеділок → імпортує й перевіряє меню (з кейтерингу або вставлене) → показує підсумок → ставить «Понеділок тижня», перебудовує «Зведення» → пропонує лист батькам | щотижня, у п'ятницю | ✅ перед повторною розсилкою попереджає |
| **1. Створити/оновити службові листи** | створює відсутні листи й рядки налаштувань, відновлює заголовки, формати, випадні списки, формулу дедлайну; переставляє колонки «Списку»; створює адмін-ключ, якщо порожньо; ставить таблиці київський час | при встановленні, після оновлення коду, коли щось «поїхало» | ✅ безпечно, дані не стирає |
| **2. Меню: імпортувати з кейтерингу або перевірити вставлене** | бере меню активного тижня з їхнього листа «Склад {тиждень}» або з нашого «Меню», перевіряє (30 позицій), записує «МенюДані» | коли меню змінилося посеред тижня | ✅ |
| **3. Згенерувати персональні посилання** | перебудовує «Токени»: посилання для кожного телефону й email активних дітей | після встановлення, додавання дітей, зміни URL | ✅ ключі не змінюються; контакти, яких немає у «Списку», зникають |
| **4. Імпорт: перенести список і баланси з листа «Імпорт»** | додає/оновлює дітей, переносить стартові баланси | при переїзді зі старої системи | ✅ баланси не подвоюються |
| **Оновити «Зведення» і «Баланс»** | перебудовує обидва листи | після ручних правок у «Замовленнях» / «Оплатах», після перемикання тижня | ✅ |
| **Позначити зміни як передані кейтерингу** | ставить `так` усім порожнім у «Журналі змін» | після передачі змін | ✅ |
| **Кейтеринг: перевірити й передати кількість порцій** | перевіряє їхній лист «Підрахунки …» (тиждень, 30 позицій), показує, що зміниться, записує наші кількості й звіряє | після дедлайну, щоранку після 09:30 | ✅ пише лише змінені клітинки |
| **Показати посилання на адмін-панель** | показує `…/exec?admin=…` | коли потрібне посилання | ✅ |
| **Увімкнути нагадування та email-сповіщення** | ставить тригери `reminderTick` (щогодини), `onPaymentEdit` і `cateringTick` (кожні 15 хв, діє лише з автопередачею) | один раз, під акаунтом, з якого мають іти листи | ✅ дублікатів не створює |
| **Надіслати батькам: відкрито замовлення на тиждень** | лист про активний тиждень усім родинам з email | якщо не надіслали під час «Нового тижня» | ⚠️ попереджає, якщо вже надсилали |
| **Надіслати баланси на email** | лист з балансом кожній активній дитині з email | за потреби, наприклад раз на місяць | ⚠️ кожен запуск — нова розсилка |
| **ДЕМО: імпортувати дітей зі шкільної таблиці** | додає вбудований список імен | тільки для демонстрації | ✅ без дублів |
| **ДЕМО: згенерувати тестові замовлення** | випадкові замовлення тим, у кого їх немає | тільки для демонстрації | ✅ наявні не чіпає |

⚠️ **ДЕМО-пункти в робочій системі не запускайте** — вони додають вигадані дані.
