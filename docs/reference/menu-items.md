# Меню «🍲 Харчування»

Меню з'являється у верхньому рядку таблиці через кілька секунд після її відкриття.
Якщо ви оновили код, а меню старе, **оновіть сторінку таблиці (F5)**: меню будується при відкритті.

Запускайте пункти **з таблиці**, а не кнопкою Run у редакторі коду. Більшість пунктів показують вікно,
і поки його не закрито, скрипт чекає (див. [Проблеми](../troubleshooting.md)).

## Щодня й щотижня

| Пункт | Що робить | Коли |
|---|---|---|
| **ℹ️ Стан системи: що працює зараз** | вікно з поточним станом: тиждень і етап, скільки батьків відповіли, меню, ціни, автоматика, кейтеринг, листи батькам, адреса форми. Кнопки «Увімкнути / Вимкнути автоматику», посилання на форму й адмінпанель | коли треба зрозуміти, що зараз працює |
| **▶ Новий тиждень: меню, дати, лист батькам** | пропонує тиждень → імпортує й перевіряє меню → показує підсумок → ставить «Понеділок тижня», перебудовує «Зведення» → пропонує лист батькам | щотижня, у п'ятницю |
| **🍽 Кейтеринг: передати кількість порцій** | перевіряє їхній лист «Підрахунки …», показує, що зміниться, записує наші кількості й звіряє | після дедлайну, щоранку після 09:30 |
| **✔ Кейтеринг: позначити зміни переданими** | ставить `так` усім непозначеним рядкам «Журналу змін» | після передачі змін |
| **🔗 Посилання на адмінпанель** | показує `…/exec?admin=…` | щоб зберегти в закладки |

**Який тиждень пропонує «Новий тиждень»:** якщо активний тиждень ще не почався і батькам про нього ще не
повідомляли — саме його (щоб довідкрити: меню + лист). Інакше — наступний після активного, але не в минулому.
Будь-який інший — вписати дату його понеділка.

## ✉️ Листи батькам

| Пункт | Що робить |
|---|---|
| **Відкрито замовлення на тиждень** | лист про активний тиждень усім родинам з email (один на адресу). Якщо вже надсилали — попередить |
| **Поточний баланс кожної дитини** | лист з балансом кожній активній дитині з email. ⚠️ Кожен запуск — нова розсилка |
| **Персональні посилання: оновити лист «Токени»** | посилання для кожного телефону й email активних дітей. Ключі не змінюються; контакти, яких немає у «Списку», зникають |

## ⚙️ Обслуговування

| Пункт | Що робить | Повторно |
|---|---|---|
| **Автоматика: увімкнути (нагадування, оплати, кейтеринг)** | ставить тригери: `reminderTick` (щогодини — нагадування), `onPaymentEdit` (лист після оплати, вписаної в таблицю), `cateringTick` (кожні 15 хв — діє лише з «Кейтеринг: автопередача» = так). Листи йдуть з вашої пошти | ✅ дублікатів не створює |
| **Автоматика: вимкнути** | прибирає ці тригери вашого акаунта | ✅ |
| **Меню тижня: імпортувати з кейтерингу або перевірити вставлене** | меню активного тижня з їхнього «Склад {тиждень}» або з нашого «Меню», перевірка 30 позицій, запис «МенюДані». Тиждень не змінює, листів не шле | ✅ |
| **Перерахувати «Зведення» і «Баланс»** | перебудовує обидва листи | ✅ |
| **Імпорт дітей і балансів зі старої системи (лист «Імпорт»)** | додає/оновлює дітей, переносить стартові баланси ([Імпорт даних](../import.md)) | ✅ баланси не подвоюються |
| **Оновити службові листи (після оновлення коду)** | створює відсутні листи й налаштування, відновлює заголовки, формати, перевірки, пояснення, формулу дедлайну; ставить київський час | ✅ дані не стирає |

## 🧪 Демо — не для робочої системи

| Пункт | Що робить |
|---|---|
| **Додати дітей зі шкільного списку** | вбудований список імен у «Список», без дублів |
| **Згенерувати тестові замовлення** | випадкові замовлення на активний тиждень тим, у кого їх немає |

У робочій системі не запускайте: це вигадані дані.
